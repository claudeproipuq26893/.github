<p>节点选得好不好，白天测不出来。上午十点一切正常，晚上九点开始转圈，这是住宅线路最常见的样子。所以选节点不是挑一份参数表，而是走一条时间线：先用三天做准备，首日做基线采样，第一周蹲晚高峰，一个月后再回头看数据。下面按这个顺序把每一步的动作、记录字段和判断门槛写清楚。</p>

<h2>一、开通前三天：先把对照组定下来</h2>
<p>没有对照就没有结论。开通前先把自己现在用的线路测一遍，作为基线；再找一条明确不同上游的线路作为参照。两条对照加一条待测，构成最小可用的实验结构。只测一条新线，你无法判断它本身好，还是恰好那天网络好。</p>
<h3>三天内要准备好的记录表</h3>
<p>字段固定为：时间、线路名、出口城市、出口 ASN、平均延迟、最大延迟、丢包率、是否掉线。用一张在线表格即可，手机也能填。字段不要临时加，加了就没法比较。每天固定三个时间点采集，宁可少也不要乱。</p>
<h3>地区覆盖怎么先做纸面筛选</h3>
<p>先看服务商的节点列表能不能覆盖你账号资料所在的城市，再看同一城市是否有两条以上不同上游。只有单点覆盖的城市，一旦这条线出问题就没有替换空间。纸面筛选能砍掉一半候选，剩下的再进实测。</p>

<h2>二、开通首日：装机与首轮采样</h2>
<img src="/tp.png" alt="住宅IP节点首日采样记录延迟与丢包的终端窗口">
<p>首日不求结论，只求数据干净。装好之后先跑十分钟稳定流量，再开始采样，避免把握手阶段的抖动算进去。采样用 ping 连打一百个包，配合 mtr 看路径，两个结果一起存。</p>
<h3>首轮要看的三条基线</h3>
<p>一是延迟基线，取平均值；二是抖动，用最大值减平均值；三是路径跳数，看有没有明显绕路。跨境线路十五跳到二十跳属正常，出现三十跳以上通常意味着绕行第三地。三条基线记下来，后面每晚对比的就是它们。</p>
<h3>首日不要做的两件事</h3>
<p>不要在首日就下单长期套餐，也不要首日就登录重要账号。线路还没验证，先拿测试账号跑流程，确认没问题再迁移。迁移顺序也建议先迁低价值账号，最后迁主力号。</p>

<h2>三、第一周：晚高峰连续观测</h2>
<p>这一周是整个流程里最关键的一段。住宅线路的带宽是和真实住户共享的，晚八点到十一点是全网最挤的时候。你要观察的不是「能不能打开」，而是「延迟涨了多少、有没有掉线、掉线后多久恢复」。</p>
<h3>五个时段的分工</h3>
<p>不同时段测的东西不一样。上午看基础质量，下午看稳定性，晚间看拥塞，深夜看维护窗口，凌晨看是否有自动重拨导致地址变化。五个时段各取一个样本，一周就是三十五个数据点，足够看出规律。</p>

<h3>判定门槛怎么定</h3>
<p>建议用相对值而不是绝对值：晚高峰平均延迟比白天基线高出三成以内算可接受，高出五成以上就要考虑换线；一周内非计划掉线超过两次，或者单次恢复超过十分钟，也建议换。绝对值门槛受地理位置影响太大，同一条线在广州和哈尔滨测出来能差一百毫秒。</p>

<h2>四、第一个月：把数据换成结论</h2>
<p>一周看趋势，一个月看稳定性。第二到第四周重点补两件事：一是把不同城市的节点各跑几天，比较地区覆盖的实际差异；二是记录替换流程的真实耗时，从提工单到新地址可用，这个数字比宣传页上的「快速响应」有用得多。</p>

<h2>常见问答</h2>
<h3>没有一整周时间，最少测多久？</h3>
<p>答：至少覆盖两个工作日的晚高峰加一个周末。两个工作日能看出拥塞规律，周末能看出维护安排。只测一个白天，等于没测。</p>
<h3>延迟高但很稳定，能用吗？</h3>
<p>答：对话类使用对延迟不敏感，两百五十毫秒以内体感差别不大；需要上传大文件或做实时操作时，延迟和带宽都要看。稳定比低延迟更重要。</p>
<h3>出口地址半夜变了，算不算问题？</h3>
<p>答：静态套餐不该变，变了要问清是否触发了自动重拨或上游调整。动态套餐本来就允许变，但频繁变动会影响登录连续性，需要评估。</p>
<h3>城市覆盖越多越好吗？</h3>
<p>答：不是。覆盖广但每个城市只有一两条线的服务商，实际替换空间很小。宁可城市少一些，每个城市有两条以上不同上游。</p>
